Femme / BloomBook — Frontend (HTML + Bootstrap 5)
==================================================

Como testar:
1. Abrir uma janela de terminal dentro da pasta "frontend"
2. Correr: python -m http.server 8080   (ou usar a extensão "Live Server" do VS Code)
3. Abrir http://localhost:8080/index.html no browser

Ligação à API:
- O ficheiro js/api.js define API_BASE = "http://localhost:3000/api"
- Ajusta essa porta/endereço quando o backend Node.js estiver pronto
- Todas as páginas usam a mesma função apiFetch() — não é preciso alterar mais nada

Estrutura:
  frontend/
    index.html            Descobrir (pesquisa de profissionais — exige login)
    login.html / registo.html
    perfil.html            Perfil público do profissional
    marcar.html            Confirmar marcação
    agenda.html            "A Minha Agenda" (cliente)
    mensagens.html         Chat associado a uma marcação (cliente)
    profissional/
      login.html, pagina.html, dashboard.html, servicos.html, agenda.html, mensagens.html
    admin/
      login.html, aprovacoes.html, avaliacoes.html, utilizadores.html
    css/style.css          Camada de marca sobre o Bootstrap (cores, tipografia)
    js/api.js              Todas as chamadas à API + gestão de sessão (localStorage)

Novidades neste bootstrap:
- "Descobrir" (index.html) passa a exigir sessão iniciada — quem não tiver
  login é redirecionado para login.html (com ?next=... para voltar à página
  pretendida depois de entrar).
- O registo de profissional (registo.html) mostra um bloco extra com upload
  de dois documentos (identificação + comprovativo de atividade), obrigatório
  antes de submeter. Após criar a conta, os ficheiros são enviados via
  multipart/form-data para POST /profissional/documentos (endpoint a criar
  no backend, autenticado com o token do profissional recém-criado).
- profissional/pagina.html tem também um bloco para reenviar/atualizar esses
  documentos mais tarde, usando o mesmo endpoint.
- js/api.js ganhou duas funções novas:
    Sessao.exigirLogin(paginaLogin)  — exige qualquer sessão iniciada
    apiUpload(path, formData)        — POST multipart/form-data com o token da sessão
